# CLAUDE.md

@AGENTS.md

The shared process comes from the template
[siraj-samsudeen/intent-driven-with-human-control](https://github.com/siraj-samsudeen/intent-driven-with-human-control),
through Copier. Change it in the template and pull it with `copier update`, not here; the
project's own values are in `.copier-answers.yml`. Add the project's own rules under `## Project`
at the end of `AGENTS.md`, which every agent reads, Codex included.

## Where the process lives

| What | Where |
|---|---|
| Modes (autopilot, build, learning), the defaults never asked, the git flow | `change-modes` skill |
| The build loop in build and learning modes | `outside-in-tdd` skill |
| Issues, ratings, blocked by, manager and task sessions, worktrees, the UI route | `issue-workflow` skill |
| Creating the repo's labels | `scripts/create-labels.sh` |
| Per-artifact rules (proposal, specs, design, adr, tasks) | `openspec/config.yaml` |
| Reviews and finding triage | `AGENTS.md` § Review guidelines |

## Claude Code wiring

The template was built for OpenCode; these files adapt it without moving any:

- `.claude/skills/` links to the skills in `.agents/skills/` and `.opencode/skills/`; the
  `openspec-*` skills and `/opsx:*` commands are generated by `openspec init --tools claude`.
  `adversarial-authoring` is the exception: a Claude Code version of the OpenCode skill.
- `.claude/agents/` holds Claude Code versions of the template's `.opencode/agent/` subagents.

On Claude Code, `adversarial-authoring` uses the Codex CLI as the reviewer when it is installed,
otherwise a different Claude model than the author, and runs only when the human agrees to it.
