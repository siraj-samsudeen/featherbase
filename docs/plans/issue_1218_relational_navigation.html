Simple like Tableau, not like Power BI

  1. One obvious default in each place. The panel shows Links, the record page opens on Form, and the Map opens on Neighbours. Most people never change anything.
  2. An option appears only where it applies. Grid only for small pairs, Why only where a chain is declared, ticking only where you may change the link.
  3. Controls sit beside what they change. Open as grid sits on its group and Focus on its box. One View ▾ menu holds the rest. No settings dialogs with tabs.
  4. Every change is remembered: in the saved view when one is open, otherwise per person per Table. The app admin sets each Table's starting default.
  5. The same pieces everywhere. One linked-rows group, one tick list, one grid, one map. Learn it once in Featherbase and it works the same in Dash and Tasker.

The final structure

One walk, recorded in the path bar. Three places, each with one job. A view appears only where it makes sense, the app admin picks each table's default, and each person's last choice is remembered.

Recommendation

  1. Lens is the record panel you already have, with three additions: relationship sections that tick and untick, a source chip on every link, and a "Why?" line on anything inherited.
  2. The path bar gains a sideways step (▾ beside the current step): jump to another floor manager at the same store without going back up. Try it on the Lens tab.
  3. Map gains a "Why" mode. Same boxes RB likes, but instead of one step out it draws the declared chain: person → role → app → permission, or person → role → report.
  4. Grid is a toggle ("Open as grid") on any relationship whose two sides are small: roles × permissions, reports × roles, departments × sections. It replaces the one-off permission matrix.
  5. Columns only as the area picker for the location and merchandise trees, never as a general view.
  6. Sentences are a label, not a screen: every permission and grant reads as one line everywhere.

The people and figures are made up. Store names are placeholders.
