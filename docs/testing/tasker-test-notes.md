# Tasker test notes

Manual test notes for Tasker: one section per scenario in the
[Tasker specs](../../openspec/TASKER.md), in the order a new user meets them
(#301).

**For the tester:** open the linked spec and do what the scenario's WHEN line
says. Then write down everything you notice under that scenario, in your own
words: what happened, what surprised you, what you expected instead. Don't judge
whether something is a bug, and leave **Triage** empty.

**For the reviewer:** give each observation one of these outcomes:

- `bug → #<issue>`: Tasker does not do what the spec promises; file an issue.
- `spec unclear → fix wording`: Tasker is fine but the spec misled the tester; fix the spec.
- `no action`: with a one-line reason.

- **Date:**
- **Site:**
- **Browser and screen size:**

Start the title of every test task with `TEST –` so test tasks are easy to find
and remove.
