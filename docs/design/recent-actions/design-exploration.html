A system that remembers where you've been

Six interactive patterns for surfacing your recent actions — rows visited, filters applied, searches run — so a repeat operator never rebuilds the same navigation twice. Every demo below is clickable and runs on the same hypothetical trail; the fake URL bar shows the real Featherbase route each click would produce (list routes already accept ?filters=… today, so a remembered view is just a remembered URL).

Same customers→same filters→same clicks, every day
The two ranking dimensions: recency and frequency ("frecency")
Trail privacy: mine is mine; the team sees changes, never views

Who has tried this

The best operator tools all converged on some slice of the same six ideas. None ships all of them together — which is the opportunity for a platform whose every screen is generated from metadata.

Slack / Linear / Raycast → Pattern 1

⌘K switchers whose empty state is your recents, ranked by frecency. Typing narrows; two keystrokes reach anything you touched this week.

Firefox awesome bar → ranking

Coined "frecency": each visit scores by age bucket, summed per target. Twenty years of proof that the simple version works.

GitHub / Slack channels → Pattern 2

A home feed of what happened around you — pushes, merges, mentions. Ambient awareness without asking anyone.

Notion / Confluence → Pattern 3

A "Recent" group pinned in the sidebar. Zero keystrokes, always visible, capped at a handful of items.

Salesforce → Patterns 3 & 4

"Recent Items" in the sidebar plus per-object MRU lists — open Accounts and see your recent accounts first, not an alphabetical wall.

Airtable / Notion databases → Pattern 5

Saved views as first-class, named, shareable objects. The habit stops being a memory and becomes an artifact.

Gmail → Patterns 1 & 5

Recent searches replayable from the search box; filter chips that turn a repeated query into a stored one.

Google Docs / Netflix → Pattern 6

"Continue where you left off" — the home screen's first job is resuming, not browsing.

Where the trail lives

Mutations are already recorded (the Version table logs every edit; activity_log/access_log cover logins, prints, exports). The only missing raw material is read-side intent — pages visited, searches run, filters applied. Three ways to capture it:

A · Client-only (localStorage)

A router hook records visits, searches and filter changes into a per-user ring buffer on the device.

Instant, private, zero server work. Device-local, no team feed, gone on cache clear.

B · Server middleware only

Log API reads automatically — no client code at all.

Rejected as primary: query-cache prefetches and refetches pollute it; it can't tell "user navigated here" from "cache revalidated".
Recommended

C · Hybrid

LocalStorage feeds the ⌘K surface with zero latency; the same events batch to the server (debounced POST /api/events, beacon on unload) into a user_event table — defined as Table metadata like everything else.

Server is truth (cross-device, feed, frecency aggregates); client is a warm mirror.

Ranking: bucketed frecency (Firefox's recipe)

Each visit contributes a weight by age; weights sum per target, and an edit weighs more than a mere view. Store one aggregate row per (user, target): visit_count, last_visit_at, score. Raw events prune after ~90 days; aggregates stay. Both orderings ship, because the owner named both dimensions: Recent (pure recency) and Frequent (frecency).

The playground

One invented trail, shared by every demo: this morning you opened Meenakshi Traders, filtered Sales Invoice to Overdue, searched "overdue chennai", and edited a payment — the same loop you run every day.

1 · ⌘K palette — recents as the empty state

Borrowed from Slack, Linear and Raycast — the owner's core ask

⌘K today focuses an inline search box. This upgrades it to a true modal palette whose empty state is the payoff: before you type a single character, your recent rows, filtered views and searches are already listed, with your frequent destinations beneath. Typing switches to search — tables, rows, commands — with results boosted by your own frecency, so your Meenakshi outranks everyone else's M-names.

Try: click the search box (or press Ctrl/⌘ K while this demo is on screen). Pick a recent item with arrow keys + Enter — the URL bar navigates. Then type "me" and watch frecency float Meenakshi Traders to the top. Esc closes.
/admin

2 · Homepage activity feed — mine and the team's

Borrowed from Slack and GitHub's home feeds

A feed card on the Home Page with two tabs. Mine shows everything I did — views, searches, filters, edits — my personal audit trail, replayable. Team shows what colleagues changed: creates, edits, submissions — never what they merely viewed. That line matters: recall is a gift to the operator, surveillance is not. The team tab is role-gated and live over the existing websocket.

Try: switch tabs, click any target to navigate, then press Simulate teammate activity to watch a live event arrive at the top of the Team feed.
/admin · Home

3 · Sidebar "Recent" — zero keystrokes

Borrowed from Notion, Confluence and Salesforce

The palette needs a keystroke; the sidebar needs nothing. A capped "Recent" group (5–8 items, deduplicated — revisiting bumps, not duplicates) sits under the Tables list, with a "Frequent" group of frecency winners beneath. This is the pattern for people who never learn shortcuts — and every team has them.

Try: click through the Recent and Frequent items — the main pane and the URL bar follow. Notice filtered views carry their filter summary right in the sidebar.
/admin

4 · Per-table recents strip

Borrowed from Salesforce's per-object MRU lists

Recall placed where the work happens: opening the Customer list shows a slim strip of your recent customers and recent filter sets for this table, above the grid. One click re-applies a whole filter set — the strip is just remembered URLs, which the list route already accepts.

Try: click the region = South · Active view chip — the grid narrows and removable filter chips appear. Click a customer chip to jump to that row. ✕ on a chip releases it.
/admin/Customer

5 · Saved views + the proactive nudge

Borrowed from Airtable and Notion; the nudge from Gmail's filter suggestions

The highest-ceiling idea here. When the system notices the same filter set applied again and again, it offers to name it. A saved view is a first-class metadata row — owner, table, filters, sort, share-with-roles — so the habit becomes an artifact you and your team can click, not a sequence you re-perform. This converts observed behavior into structure, which is exactly what a metadata platform is for.

Try: click the Overdue quick filter, then All, then Overdue again — the nudge appears. Name it, save, and it lands in the views bar with a share control. Click your new view to re-apply it instantly.
/admin/Sales Invoice

6 · Continue where you left off — and routines

Borrowed from Google Docs and Netflix; routines are the speculative stretch

The home screen's first job becomes resuming: your last row, last filtered view and last search as one-click tiles. The stretch idea: when the event log shows the same cluster of destinations opened together every morning, offer to pin them as a named workspace — the system noticing your ritual and offering to keep it.

Try: click a resume tile to navigate. Then hit Pin workspace on the routine suggestion and watch it become a persistent one-click chip row.
/admin · Home

How I'd layer them

These are layers, not rivals — they share one event stream and differ only in where recall surfaces. Ordered by leverage: what the codebase already makes cheap, first.

Ship now

⌘K palette with recents (Pattern 1), captured client-side

A router hook writes visits, searches and filter changes to localStorage; the palette gets a modal empty state with Recent / Frequent groups. Zero server change, immediate daily payoff — and it establishes the event vocabulary every later phase reuses.

Next

Sidebar Recent (3) and per-table strip (4)

Two more surfaces over the same local store — a week of UI work, no new machinery. Between them they cover the shortcut-averse and the table-centric operator.

Next

user_event table + batched POST /api/events

Server becomes the source of truth: cross-device recents, frecency aggregates, retention (raw events pruned at 90 days, aggregates kept), RLS so a user reads only their own rows. Append-only via direct insert, like audit.ts — nobody edits their own trail. Unlocks the "Mine" feed (Pattern 2) on the Home Page.

Later

Team feed (2) and Continue-where-you-left-off (6)

Team tab reads mutations from Version + activity_log — data that already exists — role-gated and live over the websocket. The resume banner and routine detection ride the same event log once it has a few weeks of history.

Own spec

Saved views + proactive nudge (Pattern 5)

The biggest single idea, and it deserves its own capability spec: a saved_view Table (owner, filters, sort, share-with-roles), the views bar in ListView, and the repeat-detection nudge. It changes what a "view" is in the product — worth deciding deliberately, not as a rider.

All data on this page is invented for the exploration. Prior art reviewed: Slack's ⌘K switcher, Linear, Raycast, Firefox's frecency algorithm (the age-bucket weights shown are Firefox's published defaults), VS Code's MRU ordering, Salesforce Recent Items and MRU lists, GitHub's home feed, Gmail search history and filter suggestions, Airtable and Notion saved views, Google Docs' resume row — and Frappe's own awesomebar recents, which are session-only and device-local; Featherbase can remember durably. Privacy stance throughout: your full trail (including views and searches) is visible to you alone; teammates and managers see changes, never reads.
