The least fix for page not found

The test says an unknown address must get "Page not found" with status 404. In this lesson the program learns to look at the address, and we look closely at what an address is made of.

What did the failing test report?

Expected 404, received 200. The program said "fine" for an address that does not exist.

Why does the test check the number as well as the words?

So that tools which read only the number are told the truth. Words alone would be a soft 404.

Question 1How do we tell the home address apart?

1. Compare the whole address as text

For example: does the address end with /?

Bites later: a link such as /?from=email does not end with /, so a home page link carrying a tracking tag would show "Page not found".

2. Take the address apart and compare only its path We chose this

One line, using the standard address reader built into Bun and every browser.

Costs: nothing yet.

3. A list of known addresses

Something like { "/": welcomePage }: if the address is not in the list, it is not found.

Why not now: with one page, a list is structure no test asks for.

4. A web framework that does the matching

It is where we are heading.

Why not now: the next lesson brings it in, as a change of tool with the tests standing guard. Writing the check by hand first gives us something to compare it with.

Question 2What do we write?

start.ts

const welcomePage = "<!doctype html><title>Featherbase</title><h1>Welcome to Featherbase</h1>";
const notFoundPage = "<!doctype html><title>Page not found</title><h1>Page not found</h1>";

Bun.serve({
  port: Number(process.env.PORT ?? 3000),
  fetch: (request) => (isHomeAddress(request) ? html(welcomePage) : html(notFoundPage, 404)),
});

function isHomeAddress(request: Request) {
  return new URL(request.url).pathname === "/";
}

function html(page: string, status = 200) {
  return new Response(page, { status, headers: { "content-type": "text/html; charset=utf-8" } });
}
  • The request is used. In lesson 2, fetch was () => … and never looked at the request. Now it is (request) => …. That one change is the whole story of this lesson.
  • The decision. condition ? a : b is a one-line if/else: the home address gets the welcome page, anything else the not-found page with 404.
  • A name for one line. isHomeAddress is a single line, and it still gets a name, because the name says what the line means. The fetch line now reads like the sentences in home.md.
  • A default. status = 200 means "if no status is given, use 200". So the welcome call stays html(welcomePage), unchanged. Adding an input with a sensible default means nothing that already works has to change.
  • A shorthand. { status, headers } is short for { status: status, headers: … }.

Question 3What is a pathname?

new URL(request.url) takes a full address apart into named pieces:

http://localhost:3210/no-such-page?from=email#top

  protocol   http
  hostname   localhost
  port       3210
  pathname   /no-such-page     ← the only piece we compare
  search     ?from=email       extra details a link can carry
  hash       #top              a spot on the page; the browser never sends it

We tried a few addresses against the program from this lesson:

address          pathname          status
/                /                 200  welcome
/?from=email     /                 200  welcome
/no-such-page    /no-such-page     404  not found
/index.html      /index.html       404  not found

The tracking tag no longer matters, because it lives in search, not in pathname. And /index.html is not the home address: Featherbase has no files at addresses, only pages it decides to show.

Question 4Why are the pages written as text in the code?

The two pages are strings of HTML inside start.ts. It looks odd. There are other ways:

1. Text strings in the code We chose this, for now

Nothing to install, and what you see is exactly what is sent.

Costs: the editor cannot check HTML inside a string. And once a page shows something a person typed, every such value must be made safe by hand before it goes in. Forget once, and a name like <script> runs as code in the reader's browser.

2. Plain .html files

Perfect for a page that never changes, like this one.

Bites later: almost every later page shows data, such as your Tables and their rows. A fixed file cannot.

3. A template language

HTML files with gaps that are filled in when the page is sent, and made safe automatically. Eta, Handlebars and Nunjucks are examples.

Costs: a second language to learn, and its mistakes show up only when a page is opened.

4. JSX on the server

HTML-like tags written inside TypeScript, such as <h1>{title}</h1>. The editor checks the tags and the types, and repeated pieces become small components.

Costs: a build setting and .tsx files. And not every JSX library makes values safe by default: the one behind Elysia's HTML add-on, which arrives in the next lesson, needs each value marked safe.

Here there are two fixed pages and nothing a person typed goes into them. Every other choice would be structure no test asks for yet. The question comes back when names from a person's file first appear on a page, and that is where to weigh it again.

Question 6Why two commits and not one?

Because each commit should do one thing you can name. The red commit says "here is a behaviour we lack". The green commit says "here is the least change that provides it". If something breaks later, the history tells you exactly which step to look at.

The habit to take away

When one line needs a moment's thought to read, give it a name. A function called isHomeAddress turns a puzzle into a sentence.

A step further

fetch sees every kind of request, not only a page being opened. A form sent to / would also get the welcome page with 200. No criterion asks about that yet. When forms arrive, the framework matches the kind of request as well as the address.

Check yourselfAnswer, then open each one

What is the pathname of http://localhost:3210/?from=email?

/. The ?from=email part is the search, not the path.

What does status = 200 in html(page, status = 200) do?

It gives the input a default. Calls that leave it out get 200, so they did not have to change.

Why give a one-line function like isHomeAddress a name?

The name says what the line means, so the place that uses it reads like plain language.

Why are the pages plain strings, and when should that be weighed again?

Two fixed pages need nothing more. Weigh it again when something a person typed first appears on a page, because then every value must be made safe.
