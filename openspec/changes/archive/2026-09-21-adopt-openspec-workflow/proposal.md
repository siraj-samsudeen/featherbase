## Why

Featherbase currently has two active-looking behavior-specification roots and an unpinned, evaluation-only OpenSpec installation. That ambiguity lets contributors change behavior without a single authoritative contract, makes legacy behavior indistinguishable from intended changes, and leaves validation dependent on whichever global CLI happens to be installed.

The owner ruled on 2026-09-21 that OpenSpec is the sole behavior specification and mandatory change workflow for Tasker and every subsequent Featherbase change. The repository must now make that ruling reproducible and enforceable.

## What Changes

- Make OpenSpec the only active behavior-specification root and the mandatory workflow for behavior changes.
- Require new features to begin with an OpenSpec change before implementation.
- Require existing features to be reverse-engineered into a verified baseline OpenSpec and committed without behavior changes before a separate change modifies them.
- Pin the OpenSpec CLI and expose strict validation through repository scripts and CI.
- Make STC traceability scan OpenSpec only and reject new competing behavior specs under `docs/specs`, while preserving design, architecture, ADR, and historical documents.
- Replace evaluation-era OpenSpec skills and commands with the official files generated by the pinned CLI, while retaining the local code, test, and spec review skills.
- Preserve the 2026-09-18 evaluation as dated evidence while superseding its recommendation against adoption.

## Capabilities

### New Capabilities
- `repository-change-workflow`: Defines the mandatory OpenSpec-first workflow, including the separate baseline-first path for existing behavior and repository validation of the contract.

### Modified Capabilities

None.

## Impact

- Root contributor guidance and the project decision record.
- `package.json`, `pnpm-lock.yaml`, setup, and CI validation.
- OpenSpec configuration and generated agent skill/command surfaces.
- STC/evidence tooling and its focused tests.
- Evaluation-era Journey specification guidance and the retired `docs/specs` root.

This change does not modify Tasker behavior specs, Tasker runtime code, schema routing, or platform-convergence work.
